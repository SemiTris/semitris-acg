# 04-文档目录规范

> 本文档定义 `docs/` 下的统一分层与命名规则，是 docs 目录的**唯一权威**（由 ADR-0002 采纳）。
> 与本文不一致的旧布局描述（含 ADR-0001、设计包「框架搭建」）均为历史记录，不再作为规范依据。

## 1. 分层规则（编号统一）

| 编号 | 目录 | 语义 | 内容 |
|---|---|---|---|
| 00-项目定义 | 为什么做 / 是什么 | 命名品牌、项目范围 |
| 01-需求 | 做什么 | PRD、用户故事与验收标准 |
| 02-技术设计 | 怎么做 | 架构设计、数据库设计、接口规范 |
| 03-接口文档 | 对外契约 | 各模块接口明细（anime/collection/…） |
| 04-计划 | 何时做 | 计划书、学习同步对照表 |
| 05-规范 | 怎么遵守 | 编码 / Git / 素材 / 文档目录规范 |
| 06-记录 | 已定事实 | `adr/` 决策记录 + `历史/` 废弃归档 |
| 07-协作 | 工作流产物 | AI 设计包 `<功能>/`（00-需求 ~ 06-变更记录） |
| assets | 非文档资产 | 可视化 HTML、图片、附件（不在 00~07 语义内） |

> 编号即流程顺序：定义 → 需求 → 设计 → 契约 → 计划 → 规范 → 记录 → 协作。

## 2. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 分类目录 | `NN-中文名`（NN=00~99） | `02-技术设计` |
| 业务文档 | `NN-名称.md`（同类内顺序） | `01-架构设计.md` |
| ADR | `NNNN-标题.md`（四位递增序号，跨项目唯一） | `0002-文档目录整合与统一规范.md` |
| 设计包 | `<功能>/00-需求.md ~ 06-变更记录.md` | `框架搭建/04-任务清单.md` |
| 资产文件 | 描述性命名，不含空格，可含 `-` / `_` | `semitris_acg-数据库设计可视化.html` |

## 3. 内容放置约定

- **废弃 / 过期文档**一律归 `06-记录/历史/`，头部保留「以 XX 为准」说明，不在工作区目录留存双版本。
- **决策记录**（架构/契约/表结构变更）写 `06-记录/adr/`，正文含：背景、决策、影响、替代方案、回滚。
- **AI 协作设计包**归 `07-协作/<功能>/`，一个功能一套 00~06，完成后标记结果在 `06-变更记录.md`。
- **图片 / HTML 等非 Markdown**归 `assets/`，Markdown 文档不直接引用 assets 以外路径。

## 4. 引用规则

- 文档内引用一律用**相对路径**（从 docs 内出发），例如 `../03-接口文档/anime.md`。
- 跨目录导航统一收敛到 `docs/README.md`（总导航），正文尽量避免散落互链。
- 链接失效时允许在路径说明处写「详见 docs/README.md」。

## 5. 维护

- 本规范由 OpenCode 维护；结构变更必须先出 ADR 再改目录。
- `docs/README.md` 是唯一导航入口，新文档必须登记在该文件目录索引中。
