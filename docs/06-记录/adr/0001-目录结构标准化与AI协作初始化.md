# ADR-0001：目录结构标准化与 AI 协作初始化

- **日期**：2026-09-18
- **状态**：已采纳
- **决策者**：SemiTris（人类）确认；OpenCode 起草

## 背景

烂尾工程顶层目录由六类中文文档目录 + `backend` + `设计可视化` 平铺组成，未按「前后端分离 / database / docs」标准布局组织；项目级 AI 协作契约缺失，导致后续 Claude Code 开工前无初始化依据。

## 决策

1. 全部文档归口 `docs/`（`00~05` 六类 + `设计可视化` + `adr/` + `agent/`），使用 `git mv` 保留历史。
2. 数据库脚本独立为顶层 `database/`，唯一入口 `database/init.sql`（原 `backend/sql/init.sql` 迁入）。
3. 新增顶层 `frontend/`（Vue `semitris-acg-web`，当前占位 README）。
4. 新增根级 `.gitignore`，覆盖 IDE / 前端 / .env / 日志；不干扰 `backend/.gitignore`。
5. 新增项目级 `AGENTS.md`，固化协作模型：OpenCode=设计/评审，Claude Code=实现，人类=最终决策者；流程为「设计包 → 确认 → 实现 → 回报 → 评审 → 验收」。

## 影响

- README 与文档内路径引用需同步更新。
- 任何 AI 会话（含未来新会话）开工前读取 `AGENTS.md` 即可初始化自身职责。
- 数据库 schema、接口契约、后端代码规范**不受影响**。

## 替代方案

- 保持原目录平铺：文档分散、database/backend 职责不清晰，否决。
- 在 backend 内建 docs：前后端共同文档错位，否决。

## 回滚

全部迁移保留 git 历史，`git mv` 反向执行即可还原；新增文件（AGENTS.md/.gitignore/frontend）可删除。
