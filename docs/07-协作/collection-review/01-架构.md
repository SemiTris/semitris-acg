# 01-架构（collection + review）

## 分层与样板

沿用既有分层（controller → service(impl) → mapper + XML），参照 User/Anime 样板落地：

```
controller/CollectionController.java / ReviewController.java
service/CollectionService.java / ReviewService.java
service/impl/CollectionServiceImpl.java / ReviewServiceImpl.java
mapper/CollectionMapper.java / ReviewMapper.java (+ @Mapper)
resources/mapper/CollectionMapper.xml / ReviewMapper.xml
```

## 关键约定

- **user_id 后端填充**：业务插入强制 `userId=DEFAULT_USER_ID(1L)`，由各 ServiceImpl 内部常量填充，不进 API；查询一律带 `user_id` 过滤。
- **连表返回**：collection 列表/按番查询 `LEFT JOIN anime` 取 `title/cover`，映射到实体非持久化字段。实体新建未持久化字段不删改。
- **事务**：review 的 add/update/delete 加 `@Transactional`，同一事务内重算 `anime.rating`，失败整体回滚。
- **rating 重算**：在 `AnimeMapper` 追加方法 `updateAnimeRating(Long animeId)`，SQL 取 `AVG(review.rating)` 回写；无评价时置 NULL。
- **时间类型**：实体统一 `java.time.LocalDateTime`（与既有实体一致；存量 User 的 `Date` 不迁移）。
