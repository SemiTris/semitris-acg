# 01-架构（recommend + file + review/page）

## 分层与样板

- recommend / review/page 沿用既有样板（controller → service(impl) → mapper + XML），参照 User/Anime 模块。
- file 为云存储形态（无表、无 Mapper），自建 FileController + OssUtil，上传至**阿里云 OSS**。

## 关键约定

- **user_id 后端填充**：recommend 插入强制 `userId=DEFAULT_USER_ID(1L)`（与既有模块一致），不进 API。
- **连表返回**：recommend `/list`、review `/page` 均 `LEFT JOIN anime` 取 `title/cover`，映射实体非持久化字段（Review 实体需新增 title/cover 字段）。
- **OSS 上传**（照用既有云存储方案）：
  - 依赖 `com.aliyun.oss:aliyun-sdk-oss:3.17.4` + Java 9 的 jaxb 三件套。
  - 配置键：`oss.endpoint / access-key-id / access-key-secret / bucket-name`，真实值只填在本地 `application.yaml`（**不入库**）。
  - objectName = `cover/{时间戳}.{扩展名}`（扩展名小写）；上传后返回公开 URL = `https://{bucket}.{endpoint}/{objectName}`。
- **配置安全（example 模板）**：
  - 仓库只提交 `application.example.yaml`（模板，键留空），真实 `application.yaml` 由开发者复制模板后填写，并被 `.gitignore` 排除。
  - 未填真实密钥时，上传调用返回失败（不启动报错、不暴露占位值）。
- **download 弃用**：OSS 直链即公开 URL，前端直接用 `anime.cover` 直链展示，不再需要后端 `/file/download` 回显接口；file.md 契约已同步更新。

## 范围说明

- recommend.update 不允许变更 `anime_id`（安利归属固定，动态 set 不含该列），与 review 一致。
- review/page 参数：pageNum/pageSize（默认 1/5）+ 可选 `animeId`；按 id 倒序，连表 title/cover。
