# 用户故事与验收标准（DoD）

> 故事格式："作为 SemiTris，我想要……，以便……"。满足全部验收条件才算完成。

## 番剧资料库

### US-A1 新增番剧
作为 SemiTris，我想要录入一部新番的完整资料，以便它出现在我的卡片墙里。
- 填写标题后提交，`POST /anime/add` 返回 `code=200`。
- 列表 / 详情能查到新记录。
- 不填必填项（标题）时前端提示并阻止提交。

### US-A2 删除番剧
作为 SemiTris，我想要删掉不再需要的番，以便保持资料库干净。
- 删除后该番从列表消失，且其**收藏 / 评价 / 推荐一并清理**（级联删除）。
- 删除前有二次确认。

### US-A3 修改番剧
作为 SemiTris，我想修改某番的信息（如集数更新），以便资料始终准确。
- `PUT /anime/update` 后详情与列表同步更新。
- 只更新传入的非空字段（动态 `<set>`）。

### US-A4 查询详情
- `GET /anime/findById/{id}` 返回该番全部字段。

### US-A5 列表分页
作为 SemiTris，我想按页浏览所有番，以便不用一次加载全部。
- `GET /anime/page` 返回 `PageInfo`（total / list / pageNum / pageSize / pages …）。
- 切换页码、修改页大小均正确。

### US-A6 多条件搜索
作为 SemiTris，我想按标题 / 类型 / 状态筛选，以便快速找到想看的番。
- 条件任意组合：标题模糊 `LIKE`、类型等值、状态等值。
- 条件全空 = 查全部。
- 分页与搜索可叠加使用。

## 收藏 / 追番

### US-C1 加入收藏
作为 SemiTris，我想把一部番标记为"想看/在看/看完/搁置/最爱"，以便管理观看计划。
- `POST /collection/add` 成功。
- 同一部番**不允许重复收藏**（数据库唯一约束，前端去重提示）。

### US-C2 更新状态与进度
作为 SemiTris，我想在追番时更新"看到第几集"和状态，以便记录进度。
- `PUT /collection/update` 只更新传入字段。
- 更新后追番列表立即反映。

### US-C3 追番列表
作为 SemiTris，我想看到我收藏的所有番（带封面和标题），以便知道哪些在追。
- `GET /collection/list` 返回**番剧信息 + 收藏状态**的连表数据。
- 支持按 `listType` 筛选（不传 = 全部）。

### US-C4 取消收藏
- `DELETE /collection/delete/{id}` 后从列表消失。

## 评价

### US-R1 写评价
作为 SemiTris，我想给一部番打分(1~10)并写感想，以便日后回忆自己的看法。
- `POST /review/add` 成功。
- 详情页能查到该评价。

### US-R2 改 / 删评价
- `PUT /review/update`、`DELETE /review/delete/{id}` 后数据一致。

### US-R3 查看某番全部评价
- `GET /review/listByAnime/{animeId}` 返回按时间倒序的评价列表。

## 推荐安利

### US-E1 推荐一部番
作为 SemiTris，我想把喜欢的番放进安利墙并写理由，以便哪天安利给别人。
- `POST /recommend/add` 成功。

### US-E2 安利墙列表
- `GET /recommend/list` 返回"番信息 + 理由 + 标签"的连表数据。

## 通用验收

- 所有接口返回 `R<T>`，`code=200` 成功 / `500` 失败。
- 所有列表接口支持 PageHelper 分页（默认 `pageNum=1`、`pageSize=5`）。
- 数据库 snake_case 字段与返回 camelCase 字段一一对应。
